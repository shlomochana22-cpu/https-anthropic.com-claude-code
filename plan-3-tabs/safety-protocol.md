# פרוטוקול בטיחות: 3 כרטיסיות כרום במקביל (הוכן 27/10/2026)

הנחות (לא נבדק חי): Breeze/Varnish עוקפים קאש למשתמש מחובר; Cloudflare מקאשת סטטי בלבד; TSF שומר הגדרות גלובליות באופציה אחת ושדות עמוד ב-postmeta; Elementor Custom Code = פוסט נפרד שמוזרק ב-head.
התנהגויות ידועות מהיומן: "פרסם" לא נקלט → document/save/publish + אימות REST; hash ×3; localStorage התמלא (27/10); התחברות פגה באמצע (27/10); חסימת הרשאה = אישור בעלים בשורה נפרדת.

## 1. סשן משותף
שלוש הכרטיסיות = עוגיית התחברות אחת. התנתקות או פקיעה באחת מפילה את כולן. אף אחד לא לוחץ "התנתק", לא נכנס ל"פרופיל אישי", לא משנה סיסמה. אם מופיע wp-login: לעצור, לא להקליד סיסמה, לכתוב "נדרשת התחברות, כרטיסייה N". אחרי התחברות מחדש כל הכרטיסיות טוענות דף ניהול ושולפות nonce חדש. בדיקת חיים כל ~20 דקות: GET /wp-json/wp/v2/users/me.

## 2. נעילות עריכה
אותו משתמש בשתי כרטיסיות = אין אזהרת נעילה, הדריסה שקטה (השמירה האחרונה מנצחת). לכן:
- כרטיסייה 1: Custom Code 4721, TSF גלובלי (Social בלבד), GBP, Maps Q&A, פייסבוק/אינסטגרם. לא פותחת שום עמוד/פוסט בעורך.
- כרטיסייה 2: עמודים חדשים (קריאה בלבד מ-4639 דרך REST), עמוד 3229 (ווידג'ט 5c0b4e23 בלבד), מונח יצרן אחד, llms.txt, GSC.
- כרטיסייה 3: רשימת IDs סגורה של service-areas + שדה qna שלהם. לא 3229, לא 1193, לא 4639, לא עמודים חדשים.
פתיחה בעורך = בעלות. אסור לפתוח עמוד של אחר בעורך "רק לראות". סוגרים עורך מיד אחרי פרסום. דף הבית 1193: אף אחד.

## 3. תופעות לוואי גלובליות
שמירת עמוד מחדשת רק את ה-CSS שלו. שמירת Custom Code 4721 משנה את ה-head של כל האתר. אסור בסשן: Regenerate CSS, Sync Library, Replace URL, Features/Experiments, Element Manager, Site Settings, עדכוני תוספים/וורדפרס, הפעלה/כיבוי תוספים.
תזמון 4721: כרטיסייה 1 מפרסמת פעם אחת ומכריזה "4721 פורסם HH:MM, מאומת בבית/דגם/עיר". כרטיסיות 2-3 מאמתות JSON-LD של העמודים שלהן רק אחרי החותמת הזו.

## 4. קאש
Purge All בטוח במקביל (האחרים רק רואים תוכן טרי). Purge רק בסוף בלוק עבודה, פעם אחת, עם הודעה "PURGE כרטיסייה N HH:MM". לא Cloudflare Purge. אימות כאורח: fetch עם `?mbv=<timestamp>` ו-`cache:'no-store'` מהקונסול, בלי ניווט בכתובת עם פרמטר ובלי `?nocache` (גוגל סורק אותו).

## 5. localStorage
מקור אחד לכולם, כבר התמלא. מפתחות `t1_` / `t2_` / `t3_` בלבד. לא מוחקים מפתחות של אחרים ולא `mb*_bk_*` ישנים. בחריגת מכסה: מוחקים רק עותקים כפולים משלך. כשאפשר, גם הורדה כקובץ. service-areas ללא רביזיות: כרטיסייה 3 חייבת גיבוי כפול. בדוח: רשימת מפתחות וגדלים.

## 6. REST במקביל
פוסטים שונים: בטוח. אותו פוסט: לעולם לא. term_content למונחים שונים: בטוח. לפני יצירת עמוד: GET ?slug=…&status=any (טיוטות יתומות אחרי קריסה).

## 7. TSF ו-llms.txt
שמירת מסך ההגדרות הגלובלי דורסת את כל המערך בערכי הטופס: כרטיסייה 1 פותחת, עורכת, שומרת פעם אחת תוך דקות, סוגרת. כרטיסיות 2-3 לא פותחות TSF גלובלי. שדות TSF של עמוד נשמרים עם הפוסט (בעלות הכרטיסייה של הפוסט). llms.txt: כרטיסייה 2 בלבד.

## 8. גוגל
חשבון אחד, 3 כרטיסיות: תקין. כרטיסייה 1: GBP + Maps + רשתות. כרטיסייה 2: GSC. 2 לא פותחת GBP, 1 לא פותחת GSC. אין יציאה מהחשבון.

## 9. דיווח וסיום
כל דיווח: `[כרטיסייה N HH:MM]` + משאבים (IDs, מפתחות storage, purge). צ'קליסט סיום (כרטיסייה 2 מריצה, 1 ו-3 מאשרות): JSON-LD בית תקין, #business פעם אחת בבית/דגם/עיר/חדש; כל העמודים החדשים 200 + canonical + ב-sitemap; 3229 ו-service-areas ללא `<br>` ו-JSON-LD תקין; Purge אחרון אחרי השמירה האחרונה; אף wp-login; מפתחות storage מתועדים.

## 10. עמידות לקריסה
כרום נסגר באמצע (קרה 27/10) → כל תוכנית אידמפוטנטית: לפני כל עריכה GET + "המחרוזת קיימת? דלג"; עמוד חדש: חיפוש slug לפני יצירה; qna: בדיקת שאלה קיימת; 4721: השוואת תוכן לפני שמירה. הבעלות לא עוברת בין כרטיסיות אחרי הפעלה מחדש. הנחיות מיוחדות נכתבות בתוך הפקודה, לא בהודעת המשך.

## כרטיס כללים (להדביק בראש כל אחת מ-3 הפקודות)
```
🔒 כללי מקבילות, כרטיסייה [N]
1. אני כרטיסייה [N]. נוגע רק ברשימת המשאבים שלי. עמוד של אחר: GET/צפייה בלבד, לא עורך.
2. לא מתנתק, לא פרופיל, לא סיסמה. wp-login → עוצר ומדווח "נדרשת התחברות, כרטיסייה [N]".
3. אסור: Regenerate CSS, Experiments, Element Manager, Site Settings, עדכונים, תוספים.
4. כרטיסייה 1 בלבד: Custom Code 4721 + TSF גלובלי + GBP. כרטיסייה 2 בלבד: GSC, llms.txt, 3229.
5. JSON-LD מאומת רק אחרי "4721 פורסם HH:MM" של כרטיסייה 1.
6. Purge פעם אחת בסוף הבלוק + הודעה. אימות אורח: fetch עם ?mbv= ו-no-store, בלי ניווט.
7. localStorage: מפתחות t[N]_ בלבד; לא מוחק של אחרים; מדווח מפתחות.
8. אותו פוסט לא נערך בשתי כרטיסיות; REST על פוסטים שונים מותר.
9. לפני כל שינוי: קיים כבר? דלג (עמיד לקריסה). עמוד חדש: בדוק slug קודם.
10. "פרסם" → document/save/publish + אימות REST + hash ×3.
11. חסימת הרשאה → אישור הבעלים בשורה נפרדת בצ'אט, לא בתוך הפקודה.
12. דיווח: [כרטיסייה [N] HH:MM] + IDs + מפתחות + purge.
```
